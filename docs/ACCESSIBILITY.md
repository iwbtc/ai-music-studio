# 无障碍说明（ACCESSIBILITY）

> 版本：R7c（2026-10-25）；适用 v1.0.x。
> 目标：核心外壳（菜单、对话框、命令面板、主要按钮）可用键盘完整操作，焦点可见，
> 尊重系统「减少动态效果」偏好；专业面板细节仍在完善。

## 1. 键盘操作路径

| 场景 | 按键 | 说明 |
|---|---|---|
| 打开命令面板 | `Ctrl+K` / `Cmd+K` | 快速执行新建/打开/保存/导出/播放/撤销/重做/帮助/设置/关于等 |
| 命令面板内 | `↑` / `↓` | 在过滤结果中移动选中项（aria-activedescendant 同步） |
| 命令面板内 | `Enter` | 执行选中命令 |
| 命令面板内 | `Esc` | 关闭命令面板（不执行命令） |
| 关闭对话框 | `Esc` | About/Help/Settings/工程/快捷键等所有对话框 |
| 在对话框内移动 | `Tab` / `Shift+Tab` | 焦点在对话框内循环（focus trap），不会跑到背景界面 |
| 播放/停止 | `Space` | 主界面 |
| 保存 | `Ctrl+S` | 保存当前命名工程 |
| 撤销/重做 | `Ctrl+Z` / `Ctrl+Y` | 与工具栏按钮一致 |
| 菜单 | `Alt`/鼠标打开后 `↑↓` `Enter` | 顶栏菜单支持键盘选择（视具体焦点） |

> 对话框关闭后，焦点会自动回到打开它的触发按钮（例如「设置」按钮/菜单项），便于继续操作。

## 2. 焦点与语义

- 所有对话框：`role="dialog"`、`aria-modal="true"`、`aria-label`（如「关于 AI 音乐工作室」「帮助中心」「设置」），
  打开时焦点落到第一个可操作项；
- 对话框内 `Tab` 循环、`Esc` 关闭；点击遮罩也可关闭；
- 图标按钮（菜单、工具栏、对话框关闭等）带 `aria-label` / `title` 文本；
- 命令面板：`role="listbox"` + `role="option"`，选中项通过 `aria-selected` / `aria-activedescendant` 暴露；
- 当前语言下 testid 不随语言变化（`data-testid` 稳定，便于自动化与辅助技术定位）。

## 3. 视觉与对比度

- 浅色主题（FL Studio 风格）主文字/背景对比度满足常规可读性；焦点使用 `:focus-visible` 描边，
  键盘导航时清晰可见（鼠标点击不额外显示描边）；
- 状态色（错误/警告/成功）不仅依赖颜色：包含文字说明与图标/符号；
- 字号以 11–14px 为主，关键标题 15–24px；可通过 Windows 显示缩放放大（见下节）。

## 4. 缩放与布局

- 支持 Windows 100%/125%/150%/200% 显示缩放（Electron 跟随系统 DPI）；
- 窗口可自由缩放；窄屏（约 1024×640 及以下）下，对话框限制最大高度并可滚动，页面不出现横向滚动条；
- 左右栏可折叠/拖宽（P7），钢琴卷帘/混音台有自适应布局。

## 5. 减少动态效果

- 应用尊重系统 `prefers-reduced-motion: reduce`：关闭/缩短大面积过渡与装饰动画
  （如弹窗淡入、卡片滑动），不影响功能；
- 播放头、电平表等**功能性实时反馈**仍会更新（它们是音频状态的必要可视化）。
- 在 Windows 设置 → 辅助功能 → 视觉效果 →「动画效果」关闭即可生效。

## 6. 已知限制（v2.0）

1. **翻译范围**：仅核心外壳双语（主菜单/对话框/命令面板/主要按钮/状态提示）；
   钢琴卷帘、混音台、效果器等专业面板细项仍有中文文案，英文界面下会保留中文（不阻断使用）；
2. **屏幕阅读器**：已提供基本对话框语义与按钮标签，但未做完整 NVDA/JAWS 全流程测试；
   画布型编辑器（钢琴卷帘/自动化曲线/波形）的可访问替代（纯键盘逐音符编辑）尚不完整；
3. **高对比度主题**：暂未提供独立高对比主题，跟随浅色主题；Windows 强制高对比模式下布局可用但配色不保证最佳；
4. **快捷键自定义**：v2.0 不支持自定义键位；
5. **字幕/音频描述**：不适用（音乐制作工具无视频内容）；
6. 触摸/触控笔操作未专门优化（基础点击可用）。

## 7. 反馈

如遇到键盘无法到达的控件、焦点丢失、对话框无法 Esc 关闭、文字被裁切等问题，
请记录：应用版本（帮助 → 关于）、操作步骤、Windows 缩放比例，并附截图/诊断日志
（帮助 →「导出诊断日志」）反馈。我们会优先修复影响阻塞操作的无障碍问题。
